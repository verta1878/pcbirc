## Gap categorization


### MZ stub gap — 117,120 B (42%)


The Family API bound-executable MZ stub. Contains the DOSCALLS/
KBDCALLS/VIOCALLS real-mode emulation layer that lets the NE binary
run on plain DOS. Generated by BIND.EXE (OS/2 SDK 1.03 tool).
Cannot be produced in DOSBox-X — requires OS/2 host or compatible
environment. **Deferred to v1.12 (byte-exact arc).**

### CODE gap — 124,445 B (45%)


269 directive handlers in Clark's binary are stubs in ours. Clark's
handlers include full UI rendering (VIO API calls), input validation,
error paths with detailed messages, screen layout management, and
OS/2-specific code paths. Our handlers return DOS defaults or are
empty stubs. Closing this gap requires implementing the handlers
against the OS/2 Family API (VioWrtTTY, KbdCharIn, DosOpen, etc.)
rather than stdio. **v1.12 work.**

### DATA gap — 35,791 B (13%)


Embedded strings, format tables, screen layouts, and directive-name
string table. v1.11.6 added error messages and version strings;
remaining gap is the full 329-directive name table, help text for
each directive, and screen layout templates. **v1.12 work.**

### NE overhead — -4,722 B (-2%)


Relocation tables, segment alignment padding, import/export tables,
and NE header metadata. Scales with segment count and import count.
Will converge automatically as code grows in v1.12.
