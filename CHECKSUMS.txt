ONE MANIFEST
------------
CHECKSUMS.sha256 and CHECKSUMS.md5, here at the root, repo-relative, are
the only checksum files in the repo.  One command from the root verifies
everything:

    sha256sum -c CHECKSUMS.sha256          (or, on Windows:  CLEANUP VERIFY)

101 files: every built or recovered binary under OUT/ and toolkit/, plus
every file changed in v0.3.4 and v0.3.5.  Each path appears exactly once
with its current hash.

IT PASSES WHETHER OR NOT 'CLEANUP RETIRE' HAS RUN.  The manifest
excludes the files that pass deletes, so a clean VERIFY does not mean the
tree is clean - it means every listed file is intact.  'CLEANUP STRAY',
run automatically at the end of VERIFY, reports checksum files outside
the root.  'git status' reports everything else.

The six per-directory checksum files are retired to attic/checksums/ with
a README.  Two of them had rotted unnoticed, because a per-directory file
has no single command that checks it: OUT/pwa153/CHECKSUMS.sha256 named
bin/ and lib/ paths that do not exist there, and toolkit/pwa153/bc31/lib
listed 13 files for a folder holding 4.  The hashes were right; the paths
were not.  Do not create another one.
