# PCBoard 15.4 Data Directory

**Status:** hexadecimal needs to provide her BBS data directory.
**Purpose:** Run PCBoard through the full crew stack on Linux.

---

## What We Need

The complete `PCB\` data tree from a working PCBoard 15.4 installation. This gets committed to the repo under `DATA/default/` as the reference configuration for the crew stack.

### Stack Wiring

```
caller (telnet:2323)
  → netmodem2irc (verta1878 — virtual FOSSIL transport)
    → FOSSIL INT 14h
      → PCBoard 15.4 (PCBOARDM.EXE via DOSBox / PCBOARD2.EXE native)
        → login prompt → main board → message bases → file areas
          → RIPscrip (kiddo/evga — graphics)
            → OpenOLMS (verta1878 — offline mail)
```

PCBoard needs its data directory to boot. Without it, the binary has nothing to display, no users to authenticate, no conferences to join.

## Required Files

### Critical (BBS won't start without these)

| File | Description | Generated By |
|---|---|---|
| `PCBOARD.DAT` | Master configuration — all paths, node count, modem settings, security levels, system name | PCBSETUP.EXE |
| `PCBOARD.SYS` | Runtime status file (150 bytes) — current node state | PCBoard creates on first run |
| `USERS` | User database — binary file, one record per user | PCBSETUP.EXE creates empty, PCBoard adds users |
| `USERS.INF` | Extended user info (email, web, gender, birthdate) | PCBoard creates |
| `CNAMES` | Conference definitions — name, path, security for each conference | PCBSETUP.EXE |
| `PWRD` | Password/security file | PCBSETUP.EXE |
| `FSEC` | File security definitions | PCBSETUP.EXE |
| `UPSEC` | Upload security definitions | PCBSETUP.EXE |
| `TCAN` | Trashcan — banned words/names | Text file |
| `USERNET.XXX` | Inter-node communication file (XXX = node number) | PCBoard creates |

### Display Files (BBS shows these to callers)

| File | When Shown | Format |
|---|---|---|
| `WELCOME` | After connect, before login | ANSI/ASCII text |
| `NEWUSER` | New user registration | ANSI/ASCII text |
| `CLOSED` | System closed message | ANSI/ASCII text |
| `WARNING` | Security warning | ANSI/ASCII text |
| `EXPIRED` | Subscription expired | ANSI/ASCII text |
| `NEWS` | After login | ANSI/ASCII text |
| `BRDM` / `BRDS` | Main menu (member/sysop) | ANSI/ASCII text |
| `CNFN` | Conference menu | ANSI/ASCII text |

### System Text

| File | Description | Generated By |
|---|---|---|
| `PCBTEXT` | All system prompts and messages (750+ strings) | MKPCBTXT.EXE |
| `CMD.LST` | Command definitions (what commands are available at each security level) | PCBSETUP.EXE |
| `PCBPROT.DAT` | File transfer protocol definitions (Zmodem, Xmodem, etc.) | PCBSETUP.EXE |
| `PCBML.DAT` | Multi-language support | PCBSETUP.EXE |
| `GROUP` | Conference group definitions | PCBSETUP.EXE |

### Conference Data (per conference)

Each conference has its own directory with:

| File | Description |
|---|---|
| `MSGS` | Message base (binary, fixed-record) |
| `MSGS.IDX` | Message index |
| `DLPATH.LST` | Download file paths |
| `ULPATH.LST` | Upload file paths |
| `DIR/` | File directories (one per file area) |

### Optional

| File | Description |
|---|---|
| `CHAT.DAT` | Chat configuration |
| `PCBSTATS.DAT` | System statistics |
| `EVENT.DAT` | Timed events (maintenance, backups) |
| `PCBFILER.DEF` | File manager definitions |
| `PCBFIDO.CFG` | FidoNet configuration |

## Path Configuration

`PCBOARD.DAT` contains absolute DOS paths (e.g., `D:\PCB\MAIN\USERS`). These must match the actual directory structure.

### For DOSBox (DOS binaries)

Mount the data directory as a DOS drive:
```
[autoexec]
mount C /path/to/pcbrevival/DATA/default
C:
PCBOARDM.EXE /N:1
```

PCBOARD.DAT paths should use `C:\` (matching the DOSBox mount).

### For Native OS/2 Binary (PCBOARD2.EXE)

Paths use OS/2 format. The OS/2 binary runs natively on Linux via the OpenWatcom DOS/4GW extender or ArcaOS compatibility layer.

### For Linux (future pcbirc)

After Phase 7 (openwatcomirc), paths will use forward slashes and the binary will run natively.

```bash
# In DOSBox with PCB directory mounted:

MKPCBTXT.EXE          # Generates PCBTEXT (system prompts)
```

PCBSETUP walks through every configuration option and creates the complete data directory structure.

## Minimum Viable Config

For testing the stack (netmodem2irc → FOSSIL → PCBoard → login prompt), the absolute minimum is:

1. `PCBOARD.DAT` — with correct paths
2. `USERS` — with at least one SYSOP account (security level 110)
3. `CNAMES` — with at least "Main Board" conference
4. `PCBTEXT` — system prompts (generated by MKPCBTXT)
5. `WELCOME` — any text file (even just "Connected to PCBoard")
6. `PWRD` — can be empty/default
7. `CMD.LST` — command definitions

The BBS will display WELCOME, prompt for login, authenticate against USERS, and drop to the main board command prompt.

## Running on Linux via Wine

**Current working configuration (verta1878):**

```
caller (telnet)
  → netmodem2irc (virtual FOSSIL transport)
    → Wine
      → PCBOARDM.EXE (DOS 386+COMM binary)
        → PCBoard 15.4 BBS
```

Wine translates DOS INT 21h calls natively — no DOSBox needed. The Borland-compiled PCBOARDM.EXE runs directly under Wine with netmodem2irc providing the FOSSIL serial layer.

### Wine Setup

```bash
# Create a WINEPREFIX for PCBoard:
export WINEPREFIX=$HOME/.pcboard
wineboot --init

# The PCB data directory maps to a Wine drive letter.
# Option 1: symlink into the Wine C: drive
ln -s /path/to/pcbrevival/DATA/default ~/.pcboard/dosdevices/c:/PCB

# Option 2: map a dedicated drive letter
ln -s /path/to/pcbrevival/DATA/default ~/.pcboard/dosdevices/d:

# PCBOARD.DAT paths must match the Wine drive mapping:
# If mounted as D:\, paths should be D:\MAIN\USERS, D:\GEN\WELCOME, etc.
# If mounted under C:\PCB\, paths should be C:\PCB\MAIN\USERS, etc.
```

### Running

```bash
# Start netmodem2irc (provides FOSSIL transport on a telnet port):
netmodem2irc --port 2323 --fossil &

# Start PCBoard under Wine:
cd /path/to/pcbrevival/OUT/DOS
wine PCBOARDM.EXE /N:1
```

The `/N:1` flag sets the node number. For multi-node, run multiple instances with `/N:2`, `/N:3`, etc.

### FOSSIL Driver

netmodem2irc provides the FOSSIL INT 14h interface that PCBOARDM.EXE uses for serial I/O. Under Wine, this works through:

1. netmodem2irc listens on a telnet port
2. When a caller connects, netmodem2irc activates the FOSSIL interface
3. Wine passes PCBoard's INT 14h calls to the FOSSIL handler
4. Characters flow: telnet → netmodem2irc → FOSSIL → PCBoard → FOSSIL → netmodem2irc → telnet

### Known Working

- **Binary:** PCBOARDM.EXE (Borland C++ 3.1 build, 974,144 bytes)
- **Wine version:** (verta1878 to confirm)
- **Transport:** netmodem2irc

### Path Fixup for Wine

The sample PCBOARD.DAT uses `D:\PCB\` paths (Salt Air BBS test config). For Wine, edit PCBOARD.DAT to match your drive mapping. PCBOARD.DAT is a text file — paths are on specific line numbers:

| Line | Content | Description |
|---|---|---|
| 23 | `D:\PCB\HELP\` | Help file directory |
| 25 | `D:\PCB\MAIN\` | Main board directory |
| 26 | `D:\PCB\PCBTEXT\` | System text directory |
| 27 | `D:\PCB\MAIN\INDEX\` | Message index directory |
| 28 | `D:\PCB\MAIN\USERS` | User database |
| 29 | `D:\PCB\MAIN\CLR` | Color definitions |
| 30 | `D:\PCB\MAIN\LCLCNAME` | Local conference names |
| 31 | `D:\PCB\MAIN\PWRD` | Password file |
| 33 | `D:\PCB\MAIN\UPSEC` | Upload security |
| 34 | `D:\PCB\MAIN\TCAN` | Trashcan |
| 35 | `D:\PCB\GEN\WELCOME` | Welcome display |

Or run PCBSETUP.EXE under Wine to regenerate PCBOARD.DAT with correct paths interactively.
