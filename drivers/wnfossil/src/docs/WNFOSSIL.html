1. Overview

1.1 Introduction

WinFOSSIL is a FOSSIL (Fido-Opus-SeaDog Serial Interface Layer) driver for Windows. It provides a high-performance serial interface for MS-DOS communication applications such as bulletin board systems (BBS), mailers, and terminal emulators running under Windows.

WinFOSSIL implements the FOSSIL specification (FTS-0017) and replaces DOS-based FOSSIL drivers such as X00, BNU, and others. It provides a fast path from the application's INT 14h interface to Windows' native serial port drivers.

Who should use WinFOSSIL: If you run MS-DOS BBS software, mailers (BinkleyTerm, FrontDoor, InterMail), or other FOSSIL-aware communication applications under Windows.

Who should not use WinFOSSIL: If you do not run FOSSIL-aware DOS applications under Windows, WinFOSSIL is not for you.

2. How To ...

2.1 Enable WinFOSSIL for a Port

  1. Open the WinFOSSIL Control Panel applet (WNFOSSIL.CPL), or right-click the system tray icon and select Configure.
  2. Select the port identifier (0 = COM1, 1 = COM2, etc.).
  3. Check the box marked Enable FOSSIL.
  4. Adjust settings for the port as required.
  5. Click OK to save your settings.
Tip: WinFOSSIL supports up to 16 ports (identifiers 0 through 15). The port identifier maps to COM1 through COM16 by default. You can change any port identifier to map to a different device name (e.g., map port 3 to LPT1 for a parallel modem).
Note: WinFOSSIL is not enabled for any port by default. You must enable each port you want accessible by FOSSIL applications.

2.2 Configure Options

The following per-port options are available:

OptionDefaultDescription
Don't release timeslice while carrier detectedONPrevents the application from releasing CPU timeslices during active connections. Some protocol engines (CE-XYZ) release timeslices during file transfers and never recover. This option forces Windows to manage timeslicing based on session inactivity instead.
Release timeslice when no port activityOFFAggressively yields CPU when the application polls for port status. Reduces overhead but may cause problems with some applications when answering calls or during file transfers.
Enable performance statisticsOFFEnables port activity monitoring. Statistics can be viewed with the System Monitor utility. May cause performance degradation on slower machines.
Auto open on first accessONAutomatically opens the FOSSIL port when an application issues a FOSSIL command without first calling Fn 04h (Initialize). Required for door programs that expect the port to be "hot" when passed from BBS software.
Keep port open during sessionOFFKeeps the port open as long as the MS-DOS session is active. Enable this for DigiBoard drivers that drop carrier when the port is closed and reopened during program handoffs.

2.3 Use VMODEM (TCP/Telnet)

VMODEM (Virtual Modem) allows FOSSIL-aware applications to make and receive TCP/IP connections using standard AT modem commands. The BBS software thinks it is talking to a Hayes-compatible modem. WinFOSSIL translates the commands to TCP/IP connections.

To dial a remote BBS via TCP:

ATDhostname:port
ATD192.168.1.100:23
ATDbbs.example.com

If no port is specified, port 23 (Telnet) is used by default.

To listen for incoming connections (auto-answer):

ATS0=23       (listen on port 23)
ATS0=2323     (listen on port 2323)
ATS0=0        (disable auto-answer)

Full AT command reference: see Section 4.2.

Note: VMODEM includes Telnet IAC filtering. It accepts Suppress Go-Ahead (SGA) and Binary mode options, which are required by most BBS software. All other Telnet options are refused to prevent option storms.

2.4 Install VFOSSIL

If you use VFOSSIL (Video FOSSIL) with your BBS software:

  1. Remove any VFOSSIL installation from your AUTOEXEC.BAT.
  2. Add VFOS_IBM (or appropriate command) to your BBS batch file before starting the mailer or BBS.
  3. Add VFOS_DEL before exiting to the DOS prompt for shutdown.
Tip: WinFOSSIL installs hooks per MS-DOS session. VFOSSIL has been known to incorrectly handle simultaneous access from multiple processes. Installing VFOSSIL independently in each session avoids this problem.

2.5 Use Non-Standard IRQs and Ports

WinFOSSIL does not require special configuration for non-standard IRQs or port addresses. If the port is properly configured in Windows (Device Manager), simply specify the port name (e.g., COM5, COM12) in WinFOSSIL. Windows handles the hardware details.

2.6 Lock or Unlock Baud Rates

WNFOSCTL.EXE is a command-line utility for locking and unlocking baud rates from batch files:

WNFOSCTL <port ID> [command [options]]

  WNFOSCTL 0 LOCK 115200    Lock COM1 to 115200
  WNFOSCTL 1 UNLOCK         Unlock COM2
  WNFOSCTL 2 STATUS         Show port 2 status

Port ID is the FOSSIL port identifier (0 = COM1, 1 = COM2, etc.).

2.7 Configure Access Security

Version 2.0.0 adds IP-based access control for VMODEM connections:

Registry: HKLM\SOFTWARE\WinFOSSIL\Security

  Whitelist    REG_MULTI_SZ    Allowed IP addresses/prefixes
  Blacklist    REG_MULTI_SZ    Blocked IP addresses/prefixes
  LogEnabled   REG_DWORD       1 = enable connection logging
  LogPath      REG_SZ          Path to log file

If a whitelist is defined, only matching IPs can connect. If a blacklist is defined, matching IPs are rejected. The blacklist is checked first.

2.8 Uninstall WinFOSSIL

Open Add/Remove Programs (or Apps & Features on Win10/11), select WinFOSSIL, and click Remove. The installer removes all files and registry entries.

3.2 ANSI Screens Displayed Slowly

If ANSI screens are drawn slowly, ensure the "Don't release timeslice while carrier detected" option is ON. Some BBS software releases CPU timeslices between screen output calls, causing Windows to deprioritize the DOS session. WinFOSSIL can override this behavior when carrier is detected.

3.3 Dropped Carrier with DigiBoard

DigiBoard drivers may drop DTR when the port is closed. If you experience carrier drops when the BBS hands off to a door program or mailer, enable the "Keep port open during MS-DOS session" option. This prevents WinFOSSIL from closing and reopening the port during handoffs.

3.4 Unable to Open FOSSIL Port

If non-FOSSIL applications cannot access a port that WinFOSSIL has enabled, ensure that "Auto open on first access" is ON. When enabled, WinFOSSIL automatically opens the FOSSIL port when any application issues a FOSSIL command, even without first calling Fn 04h (Initialize).

Common error codes when a port fails to open:

ErrorMeaning
2 (FILE_NOT_FOUND)Port does not exist. Check Device Manager.
5 (ACCESS_DENIED)Port is in use by another application.
31 (GEN_FAILURE)Hardware error. USB adapter may be disconnected.

3.5 Falcon's Eye Issues

Falcon's Eye may drop carrier or fail to recognize the FOSSIL driver. This is typically caused by Falcon's Eye checking for specific FOSSIL driver signatures. WinFOSSIL identifies as "WinFOSSIL v2.0" in the FOSSIL info block (Fn 1Bh). If Falcon's Eye checks for a specific driver name, it may not recognize WinFOSSIL.

4.1 FOSSIL API (INT 14h)

WinFOSSIL implements all 27 functions defined in FTS-0017:

01hSend character (wait)AL=char → AX=status
02hReceive character (wait)→ AL=char, AH=status
03hStatus request→ AX=status word
04hInitialize FOSSIL→ AX=1954h, BL=max fn, BH=rev
05hDeinitialize
06hDTR controlAL=0 lower, AL=1 raise
07hTimer tick→ DX:AX=tick count
08hFlush output buffer
09hPurge output buffer
0AhPurge input buffer
0BhSend character (no wait)AL=char → AX=1 if sent
0ChPeek input (no wait)→ AX=char or FFFFh
0DhKeyboard peek→ AX=key or FFFFh
0EhKeyboard read (wait)→ AX=key (AL=ASCII, AH=scan)
0FhFlow controlAL=flags
10hCtrl-C/K checkingAL=flags
11hSet cursor positionDH=row, DL=col
12hGet cursor position→ DH=row, DL=col
13hWrite char to screen (ANSI)AL=char
14hWatchdog timerAL=0 off, AL=1 on
15hWrite char to BIOS (raw)AL=char
18hRead blockCX=count, ES:DI=buf → AX=read
19hWrite blockCX=count, ES:DI=buf → AX=written
1AhBreak signalAL=0 clear, AL=1 set
1BhGet driver infoCX=size, ES:DI=buf
