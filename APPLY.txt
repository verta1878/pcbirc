TOOLCHAIN CORRECTION - WHY

  Earlier this session I posited Microsoft C 5.1 was Clark's toolchain
  based on the linker "5.10" bytes in INSTALL.EXE's NE header matching
  what I thought was MS LINK's version. That was WRONG.

  Investigation with the archives + DOSBox-X sandbox:
    - MSC 5.1's LINK stamps NE outputs with bytes 05 01 (=5.01) per
      its banner. Same for OS/2 SDK 1.03's LINK (md5-identical).
    - BC 3.1's TLINK stamps 05 0A (=5.10). Its banner says "5.1" but
      Borland encodes minor 1 as byte 0x0A (10). Microsoft encodes it
      as 0x01. Different conventions, same version-number string.
    - BWCC.DLL (Borland's Windows Custom Controls DLL) shipped in
      Clark's install output tree at
      pcb1541/install/dist/target/PCBMAIL/BWCC.DLL also has linker
      bytes 5.10 - another confirmation.

  So: BC 3.1 (in devtools/BC31.zip since forever) is Clark's compiler
  + linker. API.LIB (from OS2SDK103.zip) is the OS/2 Family API
  imports. Full toolchain identified + all archives on origin.
