WHAT THIS RELEASE DOES

  No new code. Semantic verification of our C reimplementation vs
  Clark's compiled INSTALL.EXE binary. Closes the install v1.10 arc.

  Key finding: INSTALL.EXE supports 329 total @-directives.
  Clark's PCBoard INSTALL.DAT uses 60. We implement those 60.
  The other 269 are engine capabilities unexercised by this script
  (system-query family for OS/Windows/CD-ROM/memory/video/drives/
  machine, extra string ops, file I/O @Write/@ReadLn, process
  spawning @Execute/@Spawn/@Shell, INI file ops, disk-size-conditional
  @Out variants @Out0K through @OutAbs, etc).

  install v1.10 arc: UNDERSTANDING-COMPLETE.

  Byte-exact rebuild of INSTALL.EXE itself is v1.11+ (separate arc —
  requires all 329 directives, all constraints, and vintage Borland
  C++ 4.5/5.0 toolchain targeting OS/2 Family API with linker 5.10).

WHAT'S IN THE FILE-CHANGES

  docs/pcboard-internals/INSTALL-EXE-PARITY.md  (new)
    Full parity report vs Clark's compiled INSTALL.EXE. Contents:
     - Reference binary metadata (NE format, Family API, linker 5.10,
       imports DOSCALLS/KBDCALLS/VIOCALLS)
     - The 329-vs-60 finding
     - Verification of all 60 directives we cover (54 confirmed in
       binary string table + 1 scanner keyword + 5 user variables)
     - Semantic surprises discovered:
        * Constraint: @Goto cannot exit @Finish block (we don't enforce
          but Clark's script doesn't trigger)
        * Constraint: @Size incompatible with @Requires (doesn't fire
          on @Requires @HardDisk which is what the script uses)
        * @OutXXX family: 14 disk-size-conditional output-path variants
        * @Option: parallel selection mechanism to @Group
        * @Dir: directory-path variable type alongside @QString
        * @Verbatim/@Write/@ReadLn: file I/O directives
     - Categorized listing of the 269 unused directives
     - Understanding-complete acceptance declaration
