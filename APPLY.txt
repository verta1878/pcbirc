v0.3.0: PCB/IC on the 15.4 PWA leg + Clark's 15.4 beta binaries recovered
==========================================================================
Date: 2026-09-16

Two things. IC was placed on the branch it belongs to (Phase A), and
Clark's own shipped 15.4 beta binaries — the byte-match reference the
15.4 PWA rebuild has to reproduce — were recovered after being lost for
three weeks without anyone noticing.

PHASE A — IC placed on 15.4 PWA
-------------------------------
IC is Clark's 15.4 internet upgrade, so it belongs to PWA 15.4.  It had
been sitting in pcb1541 (the IRC tree) as a staging spot for the
reconstruction work.  Originals in pcb1541/pcbic12/ are untouched.

  Source  -> pcb153/upd154/SOURCE/IC/   20 files (dos/ + os2/ preserved)
  Binaries-> OUT/pwa153/upd154/          6 files
  Data    -> OUT/data/ic12/             32 files

  OUT/data/ic12/ mirrors Clark's subdirectories rather than flattening
  them.  A flat layout is impossible: bin/PPP (150B) and bin/SLIP (151B)
  are different files from bin/DATA/PPP and bin/DATA/SLIP (377B each).
  Mirroring also removes the README.1ST conflict — it only gets renamed
  at install time.

  Not staged into ic12/: bin/rebuilt/*.exe — reconstruction comparison
  artifacts, they stay in pcb1541/pcbic12/bin/rebuilt/.

  Delta 15.4 inherits IC but ships Clark's 6 binaries unchanged: they are
  Borland C++ 3.1 (DOS) and BC++ 2.0 OS/2 output with no surviving C
  source, and the reconstruction is raw NASM db bytes Watcom cannot
  compile.  RUNINET.PPE (real PPL source), the docs and the data ARE
  inherited properly.  Recorded in pcb154/DOCS/SYSOP_154.TXT section 8,
  alongside PCBSETUP and LOCAL which are shipped-binary for the same
  reason.

CLARK'S 15.4 BETA BINARIES RECOVERED
------------------------------------
OUT/README.md referenced a clark-original/ directory that did not exist.
The binaries had lived at OUT/DOS/ and OUT/OS2/, were deleted in e4181e5
(2026-08-25, "Session Summary - Toolkit Restructure + Cleanup") and never
re-added.  Nothing flagged the absence because .gitignore's *.EXE rule
meant git could no longer see them.  There was never an OUT/pwa154/ slot.

Recovered from e4181e5^ and cross-verified against the original 1997
distribution (PCB154B inside a Team GLoW release dated 04/28/97, archived
as pcb-metaworlds on the Internet Archive).

  9 of 12 EXEs byte-identical between the two sources.  PCBOARD.SER
  identical.  The 4 documents identical once line endings are ignored —
  the repo copies had been normalized CRLF->LF.

  3 differed by exactly ONE BYTE each, at the beta date check:

      ... 26 2b 07 89 46 fe 83 7e fe 1e [76|EB] ...
           \__ Terry's signature __/     76 = JBE (check intact)
                                         EB = JMP (check bypassed)

      LOCAL.EXE     0x03249B    76 -> EB
      PCBOARD.EXE   0x03D45B    76 -> EB
      PCBOARDM.EXE  0x03CBE3    76 -> EB

  That byte pattern is the signature David Terry published in June 1997
  for disabling the 30-day beta timer (reference/pcb-1997-06-16-terry.txt).
  The repo copies were patched; the 1997 originals are not.  This matters:
  a faithful rebuild emits 76, so verifying against a patched reference
  would report three one-byte failures that are not reconstruction errors.

  OUT/clark-original/ therefore holds the UNPATCHED 1997 binaries.  The
  patched variants are kept in OUT/clark-original/beta-patched/, not
  discarded.

  Kept at OUT/ top level, not under a version directory: these are
  Clark's originals, not any one build leg's output.

  Known gaps: no .HLP files for 15.4 in any known copy, and no
  PCBUUCP.ZIP, though README.1ST refers to both.

PCBIC v1.1 ADDED TO REFERENCE
-----------------------------
reference/pcball/pcboard/ held v1.2 only.  v1.1 (05-28-96) recovered from
the same GLoW release and added beside it.  Diffing the two shows only
three binaries actually changed between releases (PCBIC.EXE, PCBIC2.EXE,
PCBICCFG.EXE).  PCBIC.HLP, PCBIC.DOC, PCBIC.PDF, PCBICEVT.EXE, TESTIC.EXE
and TESTIC2.EXE are byte-identical across both — which settles open
question 1: PCBIC.HLP is a shipped data file, not something the build
compiles.

  v1.1 also carries RUNINET.DOC (5,986B) and W95PPP.SCP (922B), neither of
  which exists in the v1.2 set or anywhere in this repo's history.
