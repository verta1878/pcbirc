WHAT WAS ACTUALLY WRONG

  You spotted it — the LST files were being ignored by .gitignore.
  
  The rule '*.lst' (lowercase) in .gitignore matches CASE-INSENSITIVELY
  on Windows and macOS git (core.ignorecase=true is the default there).
  So BLT.LST, DIR.LST, DLPATH.LST match *.lst and get silently dropped
  from every 'git add' and 'git commit'.
  
  That's exactly what APPLY-THIS-FIRST.txt on origin documented: "48
  .LST files got dropped." But it treated the symptom (missing files),
  not the cause (the gitignore rule). Without fixing the rule, the same
  files would drop AGAIN on the next Windows-side push.
